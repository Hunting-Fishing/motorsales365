## What's happening

The mismatched attribute is `data-tsd-source` — a dev-only source-location annotation injected by Lovable's tooling into every JSX element. The server render and the client hydration are computing slightly different column numbers (e.g. `63:9` vs `63:13`) for the same elements, so React reports a hydration mismatch.

Key facts:
- It's **not** in your app code — no file in `src/` writes `data-tsd-source`. It's added by a build-time transform.
- It only appears in dev/preview builds; production builds strip it.
- It doesn't affect functionality — React logs the warning and continues; the page renders and works.
- The `vr` warning above it (`Unrecognized feature: 'vr'`) is from the preview iframe's `allow` attribute in the Lovable shell, also unrelated to your app.

## Why this can't be "fixed" in your source

The attribute is generated by the tooling itself. Any patch we write in `site-layout.tsx`, `site-header.tsx`, `site-footer.tsx`, etc. would be overwritten by the same transform on the next build. The only real fixes live in the Lovable dev tooling (make the annotation deterministic across SSR + client, or skip it during SSR).

## Recommended action

Ignore the warning — it's benign dev noise. If you want it silenced in your own console while developing, the plan below adds a narrow console filter that only runs in dev.

### Steps

1. In `src/start.ts` (client entry, runs in the browser), add a small dev-only guard that wraps `console.error` and drops messages whose first argument contains both `"hydrated"` and `"data-tsd-source"`. Gate it on `import.meta.env.DEV` so production is untouched.
2. Leave all component files alone. Do not add `suppressHydrationWarning`, do not branch on `typeof window`, do not strip attributes at runtime — those either don't work for injected attrs or hide real future mismatches.

### Technical notes

- Filter must match on the message template React logs (`"A tree hydrated but some attributes…"`) AND the presence of `data-tsd-source` in the diff, so unrelated hydration mismatches (real bugs) still surface.
- No changes to route files, no SSR behavior change, no production impact.

### What I will NOT do

- Won't disable SSR for `/signup` — SEO and first-paint would regress.
- Won't add `suppressHydrationWarning` on `SiteLayout`/`SiteHeader`/`SiteFooter` — it suppresses real mismatches too and doesn't cover the deep tree here.
- Won't try to remove `data-tsd-source` in a Vite plugin — that fights Lovable's own tooling.
